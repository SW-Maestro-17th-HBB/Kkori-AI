# 전달력 평가 기준 — Worker PRD

> 리포트 2단계(음성 분석)가 세션 녹음에서 `delivery_score` 와 음성 약점 태그를 산출하는 기준.
> 이 문서는 **자기완결**이다 — `worker/src/report/audio.py` 의 임계값·산식은 이 문서를 그대로
> 이행해야 하며, 값을 바꾸면 이 문서를 먼저 고친다.
>
> **분담**: 점수 체계(0~100 정수, overall = 평가된 축 평균)·저장 위치(`REPORTS.delivery_score`,
> `audio_analyzed_at`)·완성 판정·유예 완성의 정의 원천은 백엔드(`Kkori-Backend`
> `docs/requirements/report/report.md` §1·§5)다. **지표·임계값·산식·음성 태그 판정 규칙의
> 정의 원천은 이 문서**다.

## Overview

세션 녹음 파일 하나에서 지원자의 **말 속도**와 **답변 중 침묵**을 재고, 결정적 산식으로 세션
단위 점수 하나를 낸다. LLM 은 쓰지 않는다 — 같은 녹음·대본이면 항상 같은 결과가 나온다(백엔드
PRD "음성 분석은 결정적 산식이라 재분석의 실익이 없다"의 전제).

- 입력: 녹음 파일(OGG/Opus, S3) + 대본(`interview_transcript`)의 지원자 발화 텍스트
- 출력: `delivery_score`(0~100 또는 측정 불가 NULL), 음성 약점 태그, 지표(로그)
- 트리거: `report.audio.analysis.requested` 소비 (발행 계약은 백엔드
  `docs/requirements/session/interview-recording.md` §발행 계약)

### 녹음 파일 전제

- **지원자 음성만 담긴 파일**이다 — 세션 도메인 담당자 확인(2026-09-04). 백엔드 PRD·코드의
  "듀얼 채널(왼쪽 에이전트·오른쪽 지원자)" 서술과 다르며, 그 문서의 갱신은 세션 도메인 몫이다.
- 채널 수는 가리지 않는다 — 여럿이면 평균으로 합쳐 한 채널로 본다.
- 샘플레이트는 16kHz 의 정수배만 받는다(Opus 는 항상 48kHz 로 디코딩). 그 외는 분석 실패로
  처리되어 포기 규칙 → 유예 완성 경로를 탄다.

## 1. 처리 단계

| 단계 | 방법 | 비고 |
|---|---|---|
| 디코드·리샘플 | soundfile(libsndfile 번들, ffmpeg 불필요)로 블록 단위 읽기 → 채널 평균 → FIR 저역 필터 → 정수배 솎아내기로 16kHz | 30분 녹음을 통째로 올리면 수백 MB 라 스트리밍 필수 |
| 발화 확률 | **Silero VAD** v6.2.1 ONNX 모델(MIT)을 onnxruntime 으로 실행. 512샘플(32ms) 청크마다 확률 1개 | 공식 파이썬 패키지는 torch 를 끌고 오므로 모델 파일만 레포에 둔다(`src/report/models/silero_vad.onnx`, sha256 `1a153a22…`). 에이전트(LiveKit)도 Silero 를 쓰므로 실시간·사후 판정 기준이 같다 |
| 발화 구간 | Silero 공식 `get_speech_timestamps` 후처리를 numpy 로 이식 (max_speech=∞) | 시작 임계 0.5, 종료 임계 0.35, 최소 발화 250ms, 최소 침묵 100ms, 패딩 30ms — 공식 기본값 |
| 지표 | §2 | |
| 산식·태그 | §4·§5 | |

### VAD 선택 근거 (2026-09-05)

에너지 기반 직접 구현·webrtcvad·Silero 를 비교했다. 정확도는 Silero > webrtcvad > 에너지 기반이고,
Silero 는 검증된 기본 임계값이 있어 실제 녹음으로 보정하기 전에도 신뢰할 수 있다. 비용은
onnxruntime 의존성(약 15MB)과 16kHz 리샘플 한 단계뿐이다. 무료·오픈소스(MIT)라 과금은 없다.

## 2. 지표

| 지표 | 정의 | 출처 |
|---|---|---|
| 발성 시간 `phonation_s` | 발화 구간 길이의 합 | 오디오 |
| 음절 수 `syllables` | 대본 지원자 발화(`speaker=USER`)의 음절 수 근사 — 한글 1글자 1음절, 숫자 1자리 1음절, 영단어는 모음군 수(최소 1) | 대본 |
| 말 속도 `articulation_rate` | 음절 수 ÷ 발성 시간 (음절/초) | 계산 |
| 답변 중 침묵 `pause_s` | 발화 사이 공백 중 **10초 이하**인 것의 합 | 오디오 |
| 긴 침묵 `long_pause_count` | 답변 중 침묵 중 **2초 이상**인 것의 횟수 | 오디오 |
| 답변 시간 `answering_s` | 발성 + 답변 중 침묵 | 계산 |
| 침묵 비율 `pause_ratio` | 답변 중 침묵 ÷ 답변 시간 | 계산 |
| 긴 침묵 빈도 `long_pauses_per_minute` | 긴 침묵 횟수 ÷ 답변 시간(분) | 계산 |

- **말 속도를 대본 음절 수로 재는 이유**: 오디오만으로 음절을 세는 것(음절 핵 피크 검출)은
  잡음·억양에 흔들린다. 대본은 리포트 생성 조건이라 항상 있고 결정적이다. STT 가 군말·반복을
  걷어내는 만큼 실제보다 약간 느리게 나올 수 있다 — 임계값 보정 시 감안한다.
- **10초 상한의 이유**: 파일에 면접관 음성이 없어 "면접관이 질문하는 동안의 무음"과 "답하다
  멈춘 침묵"을 가를 근거가 공백 길이뿐이다. 10초를 넘는 공백은 면접관 차례(와 그 뒤 생각하는
  시간)로 보고 침묵에서 뺀다. 답변 중 10초 넘게 멈춘 경우는 놓치지만, 면접관 차례를 침묵으로
  잘못 세는 것보다 낫다.
- 차례 시작~첫 발화(응답 지연)는 침묵으로 세지 않는다 — 생각할 시간이다.

## 3. 임계값 (잠정)

실제 녹음이 아직 없어(로컬 MinIO 에 샘플 없음) 전부 추정값이다. **실제 녹음 수십 건으로 지표
분포를 보고 확정한다** — 그 전까지 점수는 상대 비교용으로만 신뢰한다.

| 항목 | 값 | 근거 |
|---|---|---|
| 적정 말 속도 | 4.0 ~ 6.5 음절/초 | 한국어 대화체 조음 속도 문헌값(5~6)에 STT 누락 여유를 둠 |
| 침묵 비율 자유 구간 | ≤ 0.15 | 자연스러운 호흡·어절 간 틈 |
| 침묵 비율 감점 상한점 | 0.45 | 답변 시간의 절반 가까이 침묵 |
| 긴 침묵 | ≥ 2.0초 | 청자가 "멈췄다"고 느끼는 길이 |
| 잦은 침묵 태그 | 분당 2회 이상 **그리고** 총 3회 이상 | 짧은 세션의 우연을 거른다 |
| 면접관 차례 판정 | 공백 > 10초 | §2 |
| 측정 가능 최소 | 발성 ≥ 10초 그리고 음절 ≥ 30 | 이보다 적으면 통계적 의미 없음 |

## 4. 산식

```
speed_penalty  = min(40, 20 × max(0, 4.0 − rate, rate − 6.5))
pause_penalty  = min(40, 40 × max(0, pause_ratio − 0.15) / (0.45 − 0.15))
long_penalty   = min(20, 5 × long_pauses_per_minute)
delivery_score = clamp(round(100 − speed_penalty − pause_penalty − long_penalty), 0, 100)
```

- 반올림은 0.5 올림(`floor(x + 0.5)`) — `try_complete` 의 SQL `round` 와 같은 방식.
- 측정 불가(§3 최소 미달)면 `delivery_score = NULL`, `audio_analyzed_at` 은 기록한다 → 완성
  판정은 통과하고 overall 은 텍스트 3축 평균이 된다("오디오가 없으면 미평가").
- 긴 침묵은 침묵 비율에도 포함되므로 이중 감점이다 — 의도한 것이다(길게 멈춘 답변을 더 깎는다).

## 5. 음성 약점 태그

어휘집은 `evaluation-criteria.md` §2.2 이 원천이고, 판정 규칙은 이 문서가 정한다.

| 태그 | 판정 | count |
|---|---|---|
| 말 속도 빠름 | rate > 6.5 | 1 (세션 단위 판정) |
| 말 속도 느림 | rate < 4.0 | 1 |
| 잦은 침묵 | 분당 2회 이상 그리고 총 3회 이상 | 긴 침묵 횟수 |
| 군말 잦음 | **이번 범위에서 판정하지 않음** — STT 대본은 군말을 대부분 걷어내고, 오디오만으로 군말을 가려내는 결정적 규칙이 없다 | — |

- 측정 불가면 태그도 없다.
- **저장 위치**: `REPORTS.weakness_tag_summary` 에 텍스트 상위 3개 **뒤에** 덧붙인다. 텍스트
  단계와 음성 단계 어느 쪽이 먼저 끝나도 상대 몫을 지우지 않는다 — 두 단계 모두 행을 잠그고
  (`FOR UPDATE`) 자기 태그만 갈아끼운다. 재생성 시 Spring 이 `weakness_tag_summary` 를 지우면
  음성 태그도 함께 사라진다(백엔드 PRD 의 초기화 규칙 — 음성 태그 보존은 범위 밖).

## 6. 소비 규칙 (백엔드 PRD §5 이행)

| 상황 | 동작 |
|---|---|
| 리포트가 COMPLETED | 무시·ACK — 보여준 점수는 사후에 바뀌지 않는다(유예 완성된 경우 포함) |
| 리포트가 FAILED | 무시·ACK — 생성이 실패한 리포트에 음성 분석을 얹지 않는다(2026-09-05 결정). **재생성한 리포트는 음성 요청이 이미 버려졌으므로 유예 완성 경로로 전달력 없이 완성된다** |
| 이미 `audio_analyzed_at` 있음 | 중복 전달 — 분석 없이 완성 판정만 재시도 |
| 전달 횟수 ≥ 임계(3) | 포기·ACK. **FAILED 로 만들지 않는다** — 유예 완성이 마무리 |
| 리포트 로우 없음 + 지원자 발화 0건 | 정상(무응답 세션) — ACK |
| 리포트 로우 없음 + 발화 있음 | 생성 요청 소비 지연 — ACK 하지 않고 재전달 대기 |
| 다운로드 일시 오류 | 내부 재시도(지수 백오프 3회, `report_generation_jobs.retry_count` 기록) 후 예외 → PEL 회수 |
| 정상 | 저장(`delivery_score`·`audio_analyzed_at`·태그) + 완성 판정을 한 트랜잭션, 완성 시 `report.status.changed` 발행 |

음성 산출물 저장은 **PENDING·PROCESSING 리포트에만** 적용한다. 음성이 텍스트보다 먼저 끝나면
PENDING 행에 저장만 하고 상태는 건드리지 않는다 — 텍스트 단계가 끝날 때 4축으로 완성된다.

## 7. 유예 완성

텍스트 분석이 끝난 뒤 **유예 시간(`audio_grace_seconds`, 기본 600초 — 잠정, 백엔드 PRD "미정")**
안에 음성 분석이 끝나지 않은 PROCESSING 리포트를 전달력 NULL 로 COMPLETED 처리한다.

- 리포트 워커 안의 주기 작업(`audio_grace_poll_interval_s`, 기본 60초)이며
  `audio_analysis_enabled` 가 켜져 있을 때만 돈다(꺼져 있으면 텍스트만으로 즉시 완성).
- 기준 시각이 `text_analyzed_at` 인 이유: 녹음 업로드는 세션 종료 직후, 텍스트 분석은 그보다
  늦게 끝나므로 "텍스트 완료 후에도 음성이 없다"가 실제 지연의 신호다.
- 음성 소비자와의 경쟁은 조건부 UPDATE(`audio_analyzed_at IS NULL`)가 가른다 — 먼저 커밋한
  쪽만 유효하고, 늦게 온 음성은 COMPLETED 무시 규칙으로 버려진다.
- 백엔드 PRD 의 조정 배치(로우 부재 감지)는 별도 항목이며 이 스토리 범위 밖이다.

## 8. 검증 기준

- 픽스처 녹음(`tests/report/fixtures/candidate_voice.ogg` — TTS 문장 4개, 침묵 3s·1s, 면접관
  차례 15s)에서 발화 4구간·답변 중 침묵 2개가 잡히고 15s 공백은 제외되는지
- 같은 녹음·대본에서 두 번 분석한 결과가 같은지(결정성)
- 텍스트 완료 → 음성: COMPLETED + overall 4축 평균 + 이벤트 발행
- 음성 → 텍스트 완료: PENDING 에 저장만, 텍스트 완료 시 완성, 음성 태그 보존
- COMPLETED·FAILED 리포트의 음성 요청은 다운로드 없이 무시
- 중복 전달은 재계산 없이 판정만, 임계 도달은 FAILED 없이 포기
- 로우 없음: 발화 0건은 스킵, 발화 있음은 예외(재전달)
- 다운로드 실패는 예외 전파 + retry_count 3 + error_message
- 유예 초과 리포트만 delivery NULL·3축 overall 로 완성되고, 음성 완료·유예 미달 리포트는 그대로
- 측정 불가 녹음은 delivery NULL 로 완성

## 9. 미결·후속

- **임계값 보정** — 실제 녹음으로 §3 값 확정. 보정 전까지 점수는 상대 비교용
- 유예 시간 값 확정(백엔드 PRD "미정" — 녹음 업로드 소요 실측)
- `audio_analysis_enabled` 를 켜는 배포 시점
- 군말 잦음 태그 — STT 가 군말을 보존하게 되면 대본 기반으로 판정 가능
- 백엔드 PRD·코드의 듀얼 채널 서술과 "지원자 음성만" 전제의 정합 — 세션 도메인 확인 필요
