# 면접 초기 질문 생성

## Overview

사용자가 면접 세션을 시작하면 AI 면접관이 검수된 질문 목록에서 지원자에게 맞는 초기 질문 1개를 골라 음성으로 발화하는 기능 영역이다. `agent/`(kkori-agent)의 LiveKit 음성 에이전트 프로세스에서 실행되며, 에이전트가 LiveKit 룸에 디스패치되는 시점에 전달받은 세션 컨텍스트(지원 직무·이력서 요약)를 캐싱했다가 candidate 입장 후 첫 질문을 선택·발화한다. (관련 스토리: HBB1-17)

핵심 데이터 흐름: 디스패치 metadata(지원 직무·이력서 요약) → 프롬프트 주입 → Interview LLM 직행(Orchestrator 미개입)이 검수 목록에서 질문 선택 → 질문 텍스트 → TTS 발화.

**범위**: `interviewType=THIRTY_MIN`(30분, 이력서 기반)만 다룬다. 다음은 별도 스토리 범위로 이 문서에서 다루지 않는다 — 5분 CS 유형, 본론 질문(Orchestrator 평가·꼬리질문·주제 전환·첫 답변의 다음 주제 강제), 이력서 세부 경험의 질문 반영(요약은 질문 선택 판단에만 사용 — 세부 반영·RAG는 본론 질문 스토리), transcript의 Redis 적재·DB flush.

### 기능 요구사항

| No. | Function | Description |
| --- | --- | --- |
| 1 | 세션 컨텍스트 주입 | 디스패치 metadata(sessionId, interviewType, 지원 직무, 이력서 요약)를 수신·파싱해 세션 상태로 캐싱하고, 초기 질문 프롬프트에 주입 |
| 2 | 초기 질문 생성 | 검수된 질문 목록에서 첫 질문 1개를 선택(직무 치환은 코드, 선택 판단은 이력서 요약 참고)해 candidate 입장 후 음성으로 발화 |

## 1. 세션 컨텍스트 주입

### 설명

에이전트가 LiveKit job을 수락하는 시점에 디스패치 metadata를 파싱해 세션 컨텍스트를 확보하고, 초기 질문 생성에 사용할 수 있도록 준비한다.

- metadata에서 세션 컨텍스트(sessionId, interviewType, position, resumeContext)를 파싱해 에이전트 세션 상태로 캐싱한다.
- 시스템 프롬프트는 역할·지시(페르소나, 음성 제약)만 담고, 지원 직무·이력서 요약은 초기 질문 지시에 별도 주입한다. 대화 이력은 메시지 배열(ChatContext)로 관리하며 초기 질문 시점에는 이력이 없다.
- **이력서 요약(resumeContext)은 질문 선택 판단 재료로만 주입한다** — 질문 문장은 검수 목록으로 고정되므로 요약이 질문 내용에 반영되지는 않는다(세부 경험 반영·RAG는 본론 질문 스토리에서 설계).
- 예외: metadata 부재·파싱 실패 시(콘솔·metadata 없는 로컬 dispatch 테스트 포함) 직무·요약 없는 기본 질문 목록으로 폴백하고 경고 로그를 남긴다.

### 실행 조건

- `agent/.env`에 LiveKit 자격증명 존재 (`agent/.env.example` 참조).
- 에이전트는 `agent_name` **`"kkori-interviewer"`**로 등록한다(명시 디스패치 — 자동 입장 없음, 확정). 운영 입장은 Spring이 세션 생성 시 `createDispatch(agentName, metadata)`로 수행하며 metadata에 세션 컨텍스트를 담는다. metadata 없는 dispatch(로컬 검증)는 폴백 경로로 동작한다.

### 검증 기준

- metadata의 position·resumeContext가 초기 질문 지시에 반영되는지 확인(position은 표시명으로 변환).
- 미등록 position 값이 직무 미지정으로 폴백하고 경고 로그를 남기는지 확인.
- metadata 없이 시작해도 에이전트가 크래시 없이 일반 초기 질문으로 진행하는지 확인.
- 잘못된 형식의 metadata에서 파싱 예외가 처리되고 경고 로그가 남는지 확인.

### 성능 요구사항

- 없음 (컨텍스트 주입은 세션당 1회 수행).

### 인터페이스 요구사항

- 디스패치 metadata(JSON). 필드 구성·명칭 **확정** (Spring 세션 생성 스토리와 합의 완료 — 아래 4개 필드가 전부, `sessionId`는 문자열, `resumeContext` 부재 시 필드 자체를 생략):

```json
{
  "sessionId": "123",
  "interviewType": "THIRTY_MIN",
  "position": "BACKEND",
  "resumeContext": "역할: 백엔드 (프로젝트: Kkori 결제 시스템) / 기술: Java, Spring, Redis"
}
```

- `position`(지원 직무)은 **옵셔널**이며, 질문 목록의 `{position}` 문장에 **코드가 치환**한다. 없으면 해당 문장을 목록에서 제외하고 폴백한다. 직무별 프롬프트 분리는 하지 않는다 — 직무는 질문 로직을 바꾸지 않는 사실 정보이며, 직무별로 질문 로직 자체가 달라지는 요구는 `interviewType` 확장으로 다룬다.
- `position`의 원천은 **Spring이 관리하는 직무 enum**(사용자가 UI에서 선택, 현재 `BACKEND`·`FRONTEND` 2종)이다. agent는 **코드→발화용 표시명 매핑**(`BACKEND`→"백엔드", `FRONTEND`→"프론트엔드")으로 변환해 치환하며, **발화에는 매핑된 표시명만 쓰인다** — 미등록 값은 직무 미지정으로 폴백하고 경고 로그를 남긴다(임의 문자열의 발화 유입 차단, 휴리스틱 정규화 불필요). 한국어 표시명 자체도 허용한다(픽스처·과도기 호환). enum 확장 시 agent 매핑을 동기화해야 하며, 전달 형식은 **enum 코드 문자열**(`BACKEND`·`FRONTEND`)로 **확정**한다.
- `resumeContext`(이력서 요약)도 **옵셔널**이다. 질문 선택 판단 재료로만 쓰이며, 없으면 목록에서 자유 선택한다.
- 요약 출처 **확정**: Spring이 세션 생성 시 worker 분석 결과인 `resumes.structured_data`(skills/projects/experiences)에서 직무·기술·경력을 **코드로 조립**한다(별도 LLM 요약 미사용). 조립 결과가 없으면 `resumeContext` 필드를 생략한다.
- **metadata 없는 dispatch** 로컬 테스트(콘솔 모드, `lk dispatch create` metadata 생략)는 **픽스처**(환경 변수 `KKORI_POSITION_FIXTURE`·`KKORI_RESUME_CONTEXT_FIXTURE`)로 수행한다. 픽스처는 **metadata가 아예 없을 때만** 적용된다 — metadata가 존재하면 누락 필드에 픽스처를 섞지 않는다.

### 제약사항

- interviewType의 원천은 **Spring이 관리하는 면접 유형 enum**(사용자가 UI에서 선택, `THIRTY_MIN`·`FIVE_MIN` 2종)이며 이 중 `THIRTY_MIN`만 지원한다. `FIVE_MIN`(5분 CS) 파이프라인은 별도 스토리에서 설계하며, 그 전까지 수신 시 경고 로그 후 `THIRTY_MIN`과 동일하게 진행한다(**확정** — 5분 스토리 전까지 현행 유지, 동일 진행 지속 여부는 5분 설계 시 재확정).
- 이력서는 요약(resumeContext)만 주입한다. 원문·상세 RAG 결과는 주입하지 않는다(본론 질문 스토리에서 설계).

### 기타 요구사항

- metadata 원문·이력서 요약은 개인정보를 포함하므로 로그에 그대로 남기지 않는다.

## 2. 초기 질문 생성

### 설명

세션 시작 후 첫 턴에서 검수된 질문 목록 중 1개를 선택해 발화한다. 답변이 아직 없으므로 Orchestrator 평가를 거치지 않고 Interview LLM을 직행 호출한다.

- **단일 질문 + 동적 흐름**: 첫 질문 하나만 묻는다. 질문 세트(주제 목록을 미리 뽑아 순서대로 소진) 방식은 채택하지 않는다.
- 상태(state)로 "첫 질문" 여부를 판단해 초기/본론 경로를 분기한다. 초기 경로는 Orchestrator 없이 Interview LLM 직행.
- **질문 소스 = 검수된 고정 목록**: LLM이 질문을 자유 생성하지 않고, 코드 상수로 관리하는 목록(유형별 2개 — 자기소개/지원동기/경험개괄/강점, 총 8문항)에서 **선택만** 한다. few-shot 스타일 생성은 예시들을 어중간하게 섞은 저품질 질문이 나와 폐기했다.
- **선택 기준**: 단순 랜덤이 아니라 이력서 요약을 참고해 지원자 상황에 맞는 질문을 고르게 한다. 요약은 선택 판단 재료로만 쓰인다.
- **직무 치환은 코드가 처리**: `{position}` 플레이스홀더 문장(지원동기·강점형 각 1개)은 position이 있을 때 치환해 포함하고, 없으면 목록에서 제외한다(강점형은 중립 문장이 남는다).
- **선택 강제(LLM 출력 = 번호)**: LLM은 목록에서 고른 **질문 번호 하나만** 출력한다. 발화 문장은 코드가 조립한다(고정 인사말 + 선택된 목록 원문, `session.say`). 번호 파싱 실패·범위 밖·LLM 호출 실패 시 목록에서 랜덤 폴백한다 — 어떤 경우에도 발화는 목록 원문이며, 목록 밖 질문과 요약 내용(프롬프트 주입 포함)의 발화 유입이 구조적으로 차단된다. 파싱 실패 로그에 LLM 출력 원문을 남기지 않는다(요약 내용 회귀 가능성).
- **선택 시점**: 룸 연결·candidate 입장 확인 **후**, 세션 시작(마이크 입력·자동 턴 처리 활성화) **전에** 질문 선택을 완료한다 — 참가자가 입장하지 않으면 유료 선택 호출이 발생하지 않고, LLM 지연이 룸 연결을 막지 않으며, 선택 지연 동안 자동 턴 응답과 초기 질문이 경쟁하지 않는다.
- 페르소나: 진지하되 적대적이지 않은 기술 면접관. 이후 모든 질문 톤의 기준이 된다.
- **경력 전제 금지**: 지원자는 대부분 신입 또는 주니어라는 전제를 시스템 프롬프트에 명시하고, 재직 경력을 전제한 표현을 쓰지 않는다(면접 전반 적용 — 시스템 프롬프트 레벨).
- 발화 시점: candidate 입장 전까지 첫 질문을 보류하고, 입장 확인 후 발화한다.
- 출력: LLM 출력은 **질문 번호뿐**이다. 발화 텍스트와 발화 메타데이터(questionNumber=1, speaker=INTERVIEWER, questionType="initial", spokenAt)는 코드가 조립한다 — transcript 적재는 별도 스토리에서 다룬다.

### 실행 조건

- 기능 1(세션 컨텍스트 주입) 완료 또는 폴백 상태.
- STT/LLM/TTS 모델은 `agent/src/config.py` 상수로 구성(LiveKit Inference 경유, 현행 유지).

### 검증 기준

- 초기 질문이 1개만 발화되는지(질문 세트가 아님) 확인.
- 발화된 질문이 목록 원문과 **정확히 일치**하는지 확인(발화는 코드 조립 — 목록 밖 질문·요약 내용의 발화 유입은 구조적으로 불가).
- LLM 출력이 유효한 번호가 아니어도(파싱 실패·범위 밖·호출 실패) 목록 내 질문으로 폴백하는지 확인.
- position이 있으면 `{position}` 문장이 치환되어 목록에 포함되고, 없으면 제외되는지 확인.
- 발화가 plain text·구어체·한국어인지 확인(목록 검수로 보장).
- 선택 분포(특정 질문 고착 여부)는 확률적 특성상 자동 게이트로 두지 않고 미리보기 스크립트로 수동 관찰한다.
- 질문이 재직 경력을 전제하지 않는지 확인(목록 검수 + 시스템 프롬프트의 신입·주니어 전제).
- candidate 입장 전에 발화가 시작되지 않는지 확인.
- 위 항목은 음성 통합 전 텍스트 레벨에서 먼저 검증한다. 프롬프트 변경은 코드 변경과 동일하게 검증 대상이다.

### 성능 요구사항

- 정량 SLA 없음. 단, 프롬프트 크기가 첫 발화 지연에 직접 영향하므로 질문 목록·이력서 요약 외 컨텍스트를 추가하지 않는다.

### 인터페이스 요구사항

- 입력: 선택 지시(번호 매긴 질문 목록[직무 치환 완료]·이력서 요약). 대화 이력 없음.
- 출력: 질문 번호(1..N) — 코드가 인사말 + 목록 원문으로 발화를 조립한다.

### 제약사항

- Orchestrator 미개입(첫 질문 한정 — 본론 질문은 별도 스토리).
- 질문 목록은 DB가 아닌 코드 상수로 관리한다(`question_pool` 테이블 미사용 — 운영 중 질문 관리·풀 대형화 요구가 생기면 도입 검토).
- 5분 CS 유형 미지원.

### 기타 요구사항

- 출력 언어는 한국어.
